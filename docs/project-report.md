# 桌面物品清点：传统视觉模型与多模态大模型对比

## 一、项目简介

本项目针对“桌面物品清点”这一视觉任务，使用同一张图片实现并比较两种方案：

1. 传统视觉方案：使用 YOLO 完成目标检测与计数，再把 YOLO 边界框作为提示交给 MobileSAM，生成物体分割掩膜。
2. 多模态大模型方案：通过本机 Ollama 运行 Qwen3-VL 4B，直接理解图片并输出结构化物品清单。

项目提供 Streamlit 本地网页界面，可以选择图片并一键运行两种方案，随后并排查看检测框、分割掩膜和大模型物品清单。

## 二、项目目标

- 理解目标检测、图像分割和视觉大模型的输入输出差异。
- 掌握 OpenCV 图片读取、缩放、标注和保存。
- 使用 YOLO 提取类别、置信度和边界框。
- 使用 MobileSAM 根据边界框提示生成像素级掩膜。
- 调用本地视觉大模型，并使用 JSON Schema 约束结构化输出。
- 在相同输入上比较两种方案的识别效果和适用场景。
- 使用 Git 保留真实开发历史，并提供可运行的项目说明。

## 三、系统流程

```text
                              ┌─ YOLO：类别、数量、置信度、边界框
用户选择同一张桌面图片 ────────┤
                              └─ MobileSAM：根据 YOLO 框生成像素掩膜

用户选择同一张桌面图片 ───────── Qwen3-VL：名称、数量、置信度等级、判断依据

两组结果 ─────────────────────── Streamlit 页面并排展示与对比
```

## 四、技术实现

### 4.1 OpenCV 图片处理

项目使用 OpenCV 读取图片，通过 `image.shape` 获取尺寸，使用等比例缩放避免图片变形，并保存处理结果。向 Qwen3-VL 发送图片前，会在内存中把最大边长缩小到 1600，降低视觉 token 数和推理耗时，不产生额外临时图片。

### 4.2 YOLO 目标检测

项目使用轻量预训练模型 `yolo26n.pt`。模型对图片中的每个候选物体输出：

- 类别名称；
- 置信度；
- 左上角和右下角组成的边界框；
- 各类别数量统计。

检测结果同时保存为带标注的图片和 JSON，便于后续分割与方案对比。

### 4.3 MobileSAM 提示式分割

MobileSAM 不负责判断物体类别，而是根据点或框提示生成像素级掩膜。本项目自动读取 YOLO JSON 中的边界框，将每个框作为 MobileSAM 的提示，实现“检测后分割”的组合流程。

### 4.4 Qwen3-VL 本地视觉理解

项目通过 Ollama 在本机运行 Qwen3-VL 4B，并调用 `http://127.0.0.1:11434/api/chat`。提示词要求模型只统计清晰可见、可以单独拿起的主要物品，并合并同类物品。JSON Schema 将返回结果固定为：

- 场景；
- 物品名称；
- 数量；
- 置信度等级；
- 简短判断依据。

### 4.5 本地对比界面

Streamlit 页面依次运行 YOLO、MobileSAM 和 Qwen3-VL，并展示原图、检测框、分割结果和两份结构化清单。服务只监听 `127.0.0.1`，使用统计已关闭。

## 五、实验设计

最终演示图片使用无隐私的桌面场景。人工正确答案为：

| 物品 | 数量 |
|---|---:|
| 瓶子 | 1 |
| 蓝牙耳机 | 1 |
| 鼠标 | 1 |
| 笔 | 1 |

两种方案使用完全相同的输入图片。比较内容包括类别判断、数量、误检、漏检、定位能力、输出解释能力和隐私处理方式。

## 六、实验结果

### 6.1 YOLO + MobileSAM

YOLO 输出 `mouse` 2 个、`bottle` 1 个、`baseball bat` 1 个和 `dining table` 1 个。严格按目标物品类别比较：

- 正确检测：瓶子、鼠标，共 2 类；
- 漏检：蓝牙耳机、笔，共 2 类；
- 误分类或额外类别：第二个鼠标、棒球棒、餐桌，共 3 项。

MobileSAM 根据 5 个 YOLO 框生成了 5 个掩膜。它改善了物体轮廓表达，但继承了 YOLO 的类别，因此无法纠正误分类。

### 6.2 Qwen3-VL 4B

Qwen3-VL 输出饮料瓶 1、耳机盒 1、鼠标 1、笔 1。四类物品及数量均与人工正确答案对应。模型还为每项结果给出了简短的视觉判断依据。

### 6.3 方案比较

| 对比项 | YOLO + MobileSAM | Qwen3-VL 4B |
|---|---|---|
| 严格类别正确数 | 2 / 4 | 4 / 4 |
| 额外或错误类别 | 3 | 0 |
| 边界框 | 支持 | 不提供 |
| 像素掩膜 | 支持 | 不提供 |
| 开放类别理解 | 较弱 | 较强 |
| 输出解释 | 类别、置信度、坐标 | 名称、数量和文字依据 |
| 图片处理位置 | 本机 | 本机 |

## 七、结论与适用场景

YOLO + MobileSAM 适合类别相对固定、需要准确定位、计数、抠图或数据标注的任务。其推理流程明确、输出容易量化，但识别范围受到训练数据类别限制。

Qwen3-VL 更适合开放场景中的物品理解、描述和问答。本次实验中，它正确理解了预训练 YOLO 不擅长的耳机盒和笔，但没有直接提供检测框和掩膜。

实际应用中可以组合两者：由视觉大模型理解开放类别和用户意图，由检测与分割模型提供精确位置和轮廓。

## 八、隐私设计

- 原始图片和模型输出目录均被 `.gitignore` 排除。
- 私人测试图片没有加入 Git 仓库，也没有发送给在线模型。
- 最终演示使用重新拍摄的无隐私图片。
- Qwen3-VL 通过本机 Ollama 运行，只调用回环地址 `127.0.0.1`。
- 推送仓库前检查 `git status` 和暂存文件列表。

## 九、个人感悟

完成这个项目后，我对“检测、分割和理解”三种视觉能力的区别有了更具体的认识。最开始容易把 YOLO 和 SAM 都理解成“识别物体”，实际运行后发现，YOLO 主要解决类别和位置，SAM 根据提示解决轮廓，而视觉大模型更擅长开放类别和语义描述。三个模型的能力并不相同。

实验中的错误比顺利识别更有学习价值。YOLO 把蓝牙耳机识别成鼠标，把笔识别成棒球棒，说明高置信度也不等于结果一定正确。MobileSAM 能把对应区域分割出来，却不能纠正 YOLO 的类别。这让我理解到模型组合会传递上游错误，项目不能只展示成功结果，还要建立人工正确答案并分析误检与漏检。

接入 Qwen3-VL 时，原始高分辨率图片超过了模型上下文限制。通过在内存中等比例缩小图片，既解决了运行问题，也减少了推理开销。这个过程让我认识到，模型应用不仅是调用接口，还包括输入预处理、错误处理、输出约束和环境管理。

我也更加重视图片隐私。项目最终使用本地模型、回环地址和 Git 忽略规则，并重新拍摄无隐私演示图片。以后处理真实数据时，我会先确认数据流向，再决定使用本地模型还是云端服务。

Git 的持续提交记录了项目从环境准备、OpenCV、YOLO、SAM、视觉大模型到界面的完整过程。相比一次性上传，分阶段提交让我更容易定位问题，也能清楚说明每一步为什么修改。
